> 这一步没有平台规则要核对，讲的是冬瓜带人做第一版时的做法。用 Claude Code 或 Codex 前，先确认服务在你所在地区可用，遵守服务条款。

## <span class="role-tag me">🧑 你来做</span> 先判断：用一句话说清楚

动手之前，先写下这一句话：

> 「给 [谁] 用，帮他解决 [什么问题]，希望他看完 [做什么]。」

- **「给谁」越具体越好**：「宝妈」不如「刚出月子、要记喂奶时间的新手妈妈」。
- **「希望他做什么」只写一个动作**：留联系方式、付款、下载，选一个。
- 这句话写不出来，就先别让 AI 写代码。可以先让 AI 追问你，见下面「交给 AI」里的第一条提示词。

## <span class="role-tag me">🧑 你来做</span> 第一版做到哪：先砍 5 刀

冬瓜带人做第一版，先砍掉这 5 样：

| 先砍掉 | 第一版用什么代替 |
| --- | --- |
| 登录 | 不要账号，打开就能用 |
| 权限 | 不分角色，只有一种用户 |
| 在线支付 | 有人想买，先私聊人工收款 |
| 积分和客服 | 一个反馈入口（留言或留微信）就够 |
| App | 先做手机浏览器能打开的版本 |

砍完只剩三样：**一个核心功能 + 一个反馈入口 + 手机能正常打开**。数据先存在浏览器本地，后台先用表格。

每一样砍掉的功能单独做都可能卡你好几天，又都回答不了最重要的问题：**有没有人要**。只做展示和收集意向的，一个单页就够，做法见 [第一个产品先别做登录和支付：今天就能上线的单页](/articles/single-page-first/)。不会写代码怎么做出这个页面，见 [不会写代码怎么做网页](/articles/website-without-coding/)。

## <span class="role-tag ai">🤖 交给 AI</span> 需求清单让 AI 写

新建一个项目文件夹，在里面打开 Claude Code 或 Codex，按下面的提示词一条一条来：先让它追问你，再列功能、按 5 刀砍，最后把结论写进项目里的「需求.md」。

这份清单是后面每一步的范围。以后想加功能，先改清单，再让 AI 动手；AI 做着做着要加东西时，也让它先对照清单提醒你。

## <span class="role-tag me">🧑 你来做</span> 先验证有没有人要

第一版做出来，不急着往下加功能：

1. **发给真正可能会用的人**，看他们会不会用、怎么说。
2. **页面上留一个反馈入口**，把收到的原话记下来。
3. **有人愿意付钱，先私聊人工收款**。没有执照和商户号也能先收第一笔钱，具体怎么收见 [没有营业执照，第一笔钱怎么收](/articles/first-payment-without-license/)。

有人用、有人愿意付钱，再进下一步；没人要，改方向或者停，你也只花了很少的时间。

## 成本和外包，这一步先一句话带过

- **花多少钱**：按 5 刀砍完的第一版，主要花在 AI 工具上；服务器、域名、开发者账号这些在后面的步骤里分别讲，价格以官网为准。
- **要不要找外包**：想法没验证前，先自己用 AI 做个最小版本；真找外包，源码和各平台账号都要在你自己名下。
