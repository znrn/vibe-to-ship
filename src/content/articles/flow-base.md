> 协议相关的说法以 [choosealicense.com](https://choosealicense.com/licenses/) 和 GitHub 官方文档为准，本文只是帮你看懂，不是法律意见。用 Claude Code 或 Codex 前，先确认服务在你所在地区可用，遵守服务条款。

## <span class="role-tag me">🧑 你来做</span> 先判断：二开还是从零写

冬瓜的顺序是：**先找现成的开源项目改，找不到再从零写**。开源项目就是作者把代码公开放在 GitHub 等网站上、按协议允许别人使用的项目；二开就是在它的基础上改成你的产品。

| 情况 | 选哪条路 |
| --- | --- |
| 你要做的东西很常见（博客、预约、商城、表单、后台…） | 先找开源项目二开 |
| 找到的项目和你的需求差很多，改起来比重写还多 | 从零写 |
| 候选项目都跑不起来，或者早就没人维护 | 从零写，或者换一个 |
| 协议不允许你商用，或者根本没写协议 | 换一个，或者从零写 |
| 只是一个单页、一个小工具 | 直接让 AI 写，不用找底子 |

还没想清楚第一版只做什么的，先回到 [第 1 步：想清楚做什么](/flow/idea/)。只做一个单页的，见 [第一个产品先别做登录和支付：今天就能上线的单页](/articles/single-page-first/)。

## <span class="role-tag me">🧑 你来做</span> 判断一个开源项目能不能用

AI 给你列完表格，你看三件事：

### 还有没有人维护

- **最近有没有更新**：看最近一次改动是什么时候。
- **有没有被归档**：GitHub 上被作者归档（Archived）的项目是只读的，表示不再积极维护。
- **提的问题有没有人回**：别人报的问题长期没人理，你遇到问题也很难找到人。

### 能不能跑起来

不要只听 AI 说「这个项目很合适」。让它**原样**在你电脑上跑起来，你亲手打开、点几下，确认能用，再开始改。跑不起来、修了几轮还不行，就换一个。

### 开源协议允不允许你商用

协议写在项目里的 LICENSE 文件中，GitHub 项目页上一般也会显示。下面是 [choosealicense.com](https://choosealicense.com/licenses/) 对几种常见协议的归纳：

| 协议 | 允许商用 | 主要条件 |
| --- | --- | --- |
| MIT | 允许 | 保留协议和版权声明 |
| Apache-2.0 | 允许 | 保留协议和版权声明，注明你改了什么 |
| GPL-3.0 | 允许 | 保留声明、注明改动；分发时要公开源码，并用同样的协议 |
| AGPL-3.0 | 允许 | 同 GPL-3.0，而且改过的版本通过网络给别人用（比如做成网站）也要提供源码 |
| 没写协议 | 不能默认使用 | 按 GitHub 文档，没有协议就适用默认的版权法，别人不能随便复制、分享、修改 |

- 不想公开自己代码的，优先选 MIT、Apache-2.0 这类条件少的。
- README 里另外写了「仅限个人学习」「商用需授权」这类话的，按更严的那条理解，先问原作者。
- <mark class="todo">待定</mark> GPL 类协议下，做成网站对外提供服务时具体要承担哪些义务，本文不展开；拿不准就问专业人士。GitHub 文档里也说，法律问题最好咨询专业人士。

## <span class="role-tag ai">🤖 交给 AI</span> 二开或从零写

- **二开**：项目跑起来后，让 AI 对照「需求.md」列出要改的地方，你确认后一项一项改，每改完一项存一个版本。原作者的协议文件和版权声明不要删。
- **从零写**：让 AI 先说打算用什么技术、为什么，你同意后再开始，只做「需求.md」里那一个核心功能。

具体怎么跟 AI 说想法、遇到报错怎么办，在 [第 4 步：开发和报错](/flow/build/) 里讲。
